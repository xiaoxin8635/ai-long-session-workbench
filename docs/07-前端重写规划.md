# 07 — EchoDesk 前端重写规划（阶段2）

> 状态：已确认（2026-09-20，用户授权"按照你觉得最最优的方案来"）
> 目标：摈弃 Open WebUI 原前端，构建自研个性化前端，直连 memory-service API。

## 1. 背景与现状

- 当前架构：Open WebUI 官方镜像（`ghcr.io/open-webui/open-webui:main`，端口 3000）
  纯做产品壳，经 Pipe 函数（`deploy/pipes/echodesk_memory.py` v0.3.0）转发到
  memory-service 的 OpenAI-compatible 端点。**仓库内无 Open WebUI 源码**，无二开包袱。
- Pipe 桥接的已知限制：所有 Open WebUI 用户共用服务账号 `openwebui_pipe` 的个人
  workspace（单租户直通）；chat_id → session_id 映射存进程内存（重启即失）；
  external 工具确认靠"确认词完全匹配"文本协议。
- memory-service API 面已完整（10 组路由），前端直连即可，Pipe 的三类限制同步消除。

## 2. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | React 18 + TypeScript | 聊天流式 UI 生态最成熟；TS 全量类型标注 |
| 构建 | Vite 6 | 开发体验好，产物纯静态，Nginx 直接托管 |
| 样式 | Tailwind CSS 3.4 | 原子化样式快速迭代，暗色主题友好 |
| 路由 | react-router-dom 6 | 稳定，嵌套布局成熟 |
| 状态 | Zustand 5 | 轻量（auth/UI store），不引 Redux |
| HTTP | axios | 拦截器成熟（401 自动 refresh 重放） |
| SSE | fetch + ReadableStream 自解析 | 聊天是 POST-SSE，EventSource 不支持 POST |
| 测试 | vitest + @testing-library/react | 核心逻辑单测（SSE 解析、JWT 拦截器、确认流状态机） |

Node 20+（本机 24.15.0），npm 源 npmmirror；容器构建走清华 PyPI 同款思路配镜像。

### M-F1 交付明细

- 工程化：Vite 6 + React 18 + TS 5.6 + Tailwind 3.4 + ESLint 9（flat config）+ vitest 3
  （**vitest 必须 ≥3 配 vite 6**——v2 内嵌 vite 5 会产生双 vite 类型冲突）
- 认证：`api/client.ts` axios 拦截器（Bearer 附加 / 401 **单飞 refresh** 并发共享
  一次刷新后重放 / RFC 7807 problem+json 归一为 Problem）；auth store（zustand +
  localStorage persist）经 `bindAuthHooks` 与 HTTP 层解耦对接（避免循环 import）
- 页面：登录/注册双 Tab；侧边栏主布局；六个模块占位页（M-F2 起逐个充实）
- dev 端口 **3200**（3000 被 Open WebUI 占用；M-F6 生产容器才接管 3000），vite proxy
  把 `/api`、`/v1` 转发 localhost:8100
- 验证：vitest 9/9、eslint 0 错、`npm run build` 通过（gzip ≈78KB）、实机
  register 201 / login 双令牌 / me 鉴权全链路经 proxy 通

### M-F2 交付明细

- SSE 解析层：`lib/sse.ts` 通用分帧解析器（跨 chunk 撕裂 / `\r\n` 兼容 / 多行 data /
  注释行 / 流结束冲刷**未换行尾行**——后者为单测发现的真实缺陷并已修复）
- API 层：`api/sessions.ts`（CRUD + messages 分页；workspace_id 一律 query 参数，
  对齐服务端 CurrentWorkspaceQuery）、`api/chat.ts`（fetch POST + SSE，解析
  session_id/delta/tool_call/error/finish+citations）、`api/workspaces.ts`
- 状态层：`stores/chat.ts` 流式状态机（乐观追加 user+assistant 占位 → 增量回填 →
  citations/failed 落地）；长会话回放取**最近一页**（offset = max(0, total-100)）并过滤
  tool/system 消息
- 页面：`ChatPage.tsx` 三栏布局（会话列表 新建/选择/内联重命名/删除 + 消息区 自动滚底 +
  空态引导 + 错误条 + Enter 发送/Shift+Enter 换行/IME 组合保护 + textarea 自动增高）；
  `MessageBubble.tsx`（react-markdown + remark-gfm + 代码块/链接覆写 + 引用来源胶囊 +
  失败提示）；路由切至真实 ChatPage，占位页移除
- 工程注意：vite proxy target 用 **127.0.0.1**（非 localhost，规避 wslrelay [::1] 劫持）；
  探针脚本 `frontend/scripts/probe_mf2.py` 需 `trust_env=False`（本机系统代理会劫持
  localhost 请求返回 502，见 docs/04 §11）
- 验证：vitest 22/22、eslint 0 错、build 通过（gzip ≈130KB，增量来自 react-markdown）；
  实机探针全链路：register→login→workspace→流式对话（session_id 自动捕获 / 5 delta 片 /
  finish stop / [DONE]）→ 会话列表与历史回放一致

### M-F3 交付明细

- API 层：`api/chat.ts` 重构出共享 `openStream`（登录校验 + RFC 7807 detail 归一）与

## 6. 关键决策与风险

1. **Open WebUI 处置**：M-F6 后从 compose 退役（不再运行）；Pipe 代码归档保留于
   `deploy/pipes/`（历史可追溯）；`/v1/tasks/completions` 端点保留（评测 judge 仍在用）。
2. **License 声明**：不再二开 Open WebUI → README 由"基于 Open WebUI 二次开发"改为
   诚实表述"早期采用 Open WebUI 作为产品壳验证，现已替换为自研前端"；
   docs/01 上游来源声明同步修订。
3. **多租户升级**：前端直连后每用户独立账号 + 独立 workspace（消除 Pipe 单租户直通）。
4. **JWT 存储**：localStorage（内网工具型产品可接受；XSS 面由 React 转义 + 不用
   dangerouslySetInnerHTML 渲染用户内容控制）。token 仅内存 + localStorage，不进 cookie。
5. **SSE 反代**：Nginx 对 `/v1/` location 关闭 `proxy_buffering`，`X-Accel-Buffering: no`。
6. **3000 端口交接**：web 容器接管 3000，用户书签不变；memory-service 8100 等端口不变。
