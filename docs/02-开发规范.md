# 开发规范 — AI 长会话知识工作台

> 本文约束本仓库的全部开发行为（人类开发者与 AI 辅助开发均适用）。配套的 `CLAUDE.md` 是其面向 AI 会话的精简版。
>
> 文档版本：v1.0（2026-09-18）

---

## 1. 工具链

| 工具 | 用途 | 说明 |
|---|---|---|
| Python 3.11+ | 运行时 | 统一版本，避免 3.12+ 依赖兼容问题 |
| uv（或 pip + venv） | 依赖管理 | 依赖固定在 `pyproject.toml` + `uv.lock` |
| ruff | lint + format | 替代 black/isort/flake8，配置见 `pyproject.toml` |
| mypy | 类型检查 | 对 `app/` 目录启用（宽松起步，逐步收紧） |
| pytest + httpx | 测试 | 单元 / 集成 / 隔离测试 |
| pre-commit | 提交前检查 | ruff + 密钥扫描（gitleaks） |
| Docker Compose | 本地环境 | 全栈一键启动 |

## 2. 代码风格（ruff 强制）

- 行宽 100；缩进 4 空格；UTF-8；LF 换行
- import 排序：标准库 → 第三方 → 本地，分组空行
- 字符串统一双引号；f-string 优先于 `%` / `.format()`
- 单文件不超过 400 行，单函数不超过 60 行（软限制，超限考虑拆分）

## 3. 注释规范（强制）

三类注释缺一不可，注释与代码必须同步更新：

### 3.1 文件级 docstring

```python
"""记忆抽取管线：从对话轮次中抽取事实/偏好/任务状态并入库。

职责：结构化抽取 → 打分 → 去重 → 冲突仲裁 → 写入 memories 表。
设计文档：docs/01-项目开发内容与实现方案.md §5.2.2
"""
```

### 3.2 类级 docstring

```python
class MemoryExtractor:
    """记忆抽取器。

    Attributes:
        llm: 抽取用小模型客户端（与主对话模型分离以降低成本）。
        dedup_threshold: 向量相似度去重阈值，默认 0.92。
    """
```

### 3.3 函数级 docstring

```python
def extract(self, messages: list[Message]) -> list[ExtractedFact]:
    """从一轮对话中抽取候选记忆。

    Args:
        messages: 本轮 user/assistant 消息对。

    Returns:
        抽取结果列表，含 key、content、confidence、memory_type。

    Raises:
        LLMTimeoutError: 抽取模型超时（默认 10s），由调用方降级为跳过本轮。
    """
```

## 4. 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 模块/函数/变量 | snake_case | `memory_retriever.py` / `build_context()` |
| 类 | PascalCase | `ContextBuilder` |
| 常量 | UPPER_SNAKE_CASE | `DEFAULT_TOKEN_BUDGET` |
| 数据库表 | 复数 snake_case | `memories` / `token_usages` |
| 枚举值 | 小写串 | `memory_type = "semantic"` |
| API 路径 | kebab 或小写复数资源 | `/api/memories` |
| 环境变量 | UPPER_SNAKE_CASE | `MEMORY_SERVICE_PORT` |
| 分支 | `feature/<模块>` `fix/<问题>` | `feature/memory-pipeline` |

## 5. 分支模型与提交规范

### 5.1 分支

- `main`：随时可运行、可演示；只接受合并，不直接推送大改动
- `feature/<模块名>`：新功能分支，如 `feature/context-builder`
- `fix/<问题名>`：修复分支
- 单分支生命周期不超过 3 天，及时合并避免漂移

### 5.2 Conventional Commits

格式：`<type>: <中文描述>`（描述说明"做了什么"，可追加正文说明"为什么"）

| type | 用途 | 示例 |
|---|---|---|
| feat | 新功能 | `feat: 记忆抽取管线支持冲突仲裁` |
| fix | 修 Bug | `fix: 修复跨 workspace 记忆泄漏` |
| docs | 仅文档 | `docs: 补充 API 设计章节` |
| refactor | 重构（不改行为） | `refactor: 抽离 ContextBuilder 预算配置` |
| test | 测试 | `test: 记忆冲突检测用例` |
| perf | 性能 | `perf: 摘要增量缓存降低 token 成本` |
| chore | 构建/工具 | `chore: 初始化仓库与开发规范` |

### 5.3 提交自查

每次 `git add` 前自查：无 `.env`、无密钥、无 `data/`、`volumes/`、`node_modules/`、无 print 调试残留。

## 6. 测试规范

1. 目录：`services/memory-service/tests/`，文件名 `test_<模块>.py`
2. 分层：
   - **单元测试**：记忆打分、预算分配、裁剪逻辑等纯函数，mock 外部依赖
   - **集成测试**：API → DB → 向量库（docker compose 起依赖）
   - **隔离测试（强制）**：workspace A 无法读写 workspace B 的会话/记忆/知识库，作为回归用例长期保留
3. 要求：新功能必须附带测试；修 Bug 必须先写复现用例再修复
4. 运行：`pytest -q`；提交前必须全绿

## 7. 数据库变更规范

1. ORM 模型修改 → `alembic revision --autogenerate -m "<描述>"` → 人工检查生成的迁移（autogenerate 会漏多列约束变更）→ `alembic upgrade head`
2. 已提交的迁移文件禁止修改，只能追加新迁移
3. 破坏性变更（删列/改类型）必须两步走：先加新列双写，下个版本再清理

## 8. 安全规范

1. 密钥只存在于 `.env`（git 已忽略）；`.env.example` 提供模板但不放真实值
2. 用户输入一律 Pydantic 校验；SQL 走 ORM/参数化；禁止 `f-string` 拼 SQL
3. JWT 鉴权中间件统一注入，路由不得绕过；repository 层强制 `workspace_id` 过滤
4. 工具调用按 `risk_level` 分级：read_only 自动、write 审计、external 需用户确认
5. 日志禁止输出密钥、完整用户内容（只记摘要与长度）
6. 提交历史中发现密钥：立即吊销该密钥 + `git filter-repo` 清理历史 + 强制全员重新 clone

## 9. 文档同步规范（强制）

| 改动类型 | 必须同步更新 |
|---|---|
| 新增/修改 API | `docs/01` 第 6 章 API 表 + 模块章节 |
| 修改数据模型 | `docs/01` 第 4 章表结构 |
| 修改模块行为 | `docs/01` 对应模块小节 + 代码注释 |
| 新增配置项 | `.env.example` + `docs` 配置说明 |
| 评测指标变化 | `docs/01` 第 8 章 + `evals/README` |

原则：**代码与文档不一致视为 Bug**，发现即修。

## 10. AI 协作开发流程（本项目大量使用 Claude Code）

1. **任务拆小**：一次会话只做一个模块或一个明确任务，先读 `docs/01` 对应章节再动手
2. **先设计后编码**：涉及数据流/接口变更时，先在会话中给出设计要点并经用户确认
3. **验收标准**：每任务完成后必须提供——改动文件清单、测试运行结果、文档更新情况
4. **发现即修**：发现任何 Bug 立即修复并按蟑螂法则排查同类问题，不允许"先记下来以后修"
5. **诚实汇报**：测试失败要如实贴输出；未实现的功能不得声称完成
