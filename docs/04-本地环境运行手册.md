# 本地环境运行手册

> 描述 `deploy/docker-compose.yml` 管理的本地开发环境：Open WebUI + memory-service + PostgreSQL + Redis。
>
> 文档版本：v1.1（2026-09-18，M1 Day 2 增加 memory-service）
>
> 文档版本历史：v1.0（2026-09-18，M1 Day 1 初始三服务）

---

## 1. 服务清单

| 服务 | 容器名 | 镜像 | 端口 | 用途 |
|---|---|---|---|---|
| open-webui | workbench-openwebui | ghcr.io/open-webui/open-webui:main | 3000 | 工作台产品壳 |
| memory-service | workbench-memory | 本地构建（`services/memory-service`） | 8100 | 自研核心：记忆 / 上下文 / Agent |
| postgres | workbench-postgres | pgvector/pgvector:pg16 | 5432 | 业务数据库（会话/消息/记忆） |
| redis | workbench-redis | redis:7-alpine | 6379 | 工作记忆 / 缓存 / 分布式锁 |

> 预留：Milvus(19530)、Langfuse(3001) 后续里程碑加入。

## 2. 首次启动

```powershell
# 0. 前置：启动 Docker Desktop 并等待就绪
Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"

# 1. 检查端口占用（规范要求，启动前必做）
netstat -ano | findstr ":3000 :5432 :6379"   # 无输出 = 空闲

# 2. 生成 .env（模板在 deploy\.env.example，密码用随机强密码）
#    PowerShell 生成 32 位十六进制密码：
-join ((1..32) | ForEach-Object { '{0:x}' -f (Get-Random -Max 16) })

# 3. 启动
docker compose -f "D:\ai_play\ai_long_project\deploy\docker-compose.yml" up -d

# 4. 验证
docker compose -f "D:\ai_play\ai_long_project\deploy\docker-compose.yml" ps
Invoke-WebRequest -Uri "http://localhost:3000/health" -UseBasicParsing   # Open WebUI，期望 200
Invoke-WebRequest -Uri "http://localhost:8100/healthz" -UseBasicParsing  # memory-service 存活
Invoke-WebRequest -Uri "http://localhost:8100/readyz" -UseBasicParsing   # 就绪（PG+Redis 连通）
```

### 2.1 数据库迁移（模型变更后执行）

```powershell
# 容器内执行（推荐，与环境一致）
docker exec workbench-memory alembic upgrade head

# 本地裸跑方式（uv 环境，需设置 MEMORY_SERVICE_DATABASE_URL 指向 localhost）
Set-Location "D:\ai_play\ai_long_project\services\memory-service"
$env:MEMORY_SERVICE_DATABASE_URL = "postgresql+asyncpg://workbench:<密码>@localhost:5432/workbench"
uv run alembic upgrade head
```

> 注意：`alembic.ini` 必须保持 ASCII-only（Windows configparser 按 GBK 读取，中文注释会解码失败）。

### 2.2 memory-service 本地开发模式（不走容器）

```powershell
Set-Location "D:\ai_play\ai_long_project\services\memory-service"
uv sync                                    # 安装依赖（含 dev 组）
uv run ruff check . && uv run ruff format --check .
uv run pytest -q                           # 冒烟测试
uv run uvicorn app.main:app --port 8100 --reload   # 热更新开发模式
```

### 2.3 LLM 配置（M-08 Chat 端点）

`/v1/chat/completions` 需要 OpenAI 兼容的模型服务，在 `deploy\.env` 中配置：

```ini
# DeepSeek 示例
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-xxxx
LLM_MODEL=deepseek-chat

# 通义（OpenAI 兼容模式）示例
# LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
# LLM_MODEL=qwen-plus
```

改完执行 `docker compose -f $cc up -d memory-service` 重建生效。
未配置时端点返回 503（`llm_not_configured`），属预期行为。

## 4. 日常操作

```powershell
$cc = "D:\ai_play\ai_long_project\deploy\docker-compose.yml"

# 启动 / 停止 / 重启
docker compose -f $cc up -d
docker compose -f $cc stop
docker compose -f $cc restart

# 查看日志（-f 跟随）
docker compose -f $cc logs -f open-webui
docker compose -f $cc logs -f postgres

# 单独重建某服务（改了 compose 中该服务定义后）
docker compose -f $cc up -d --force-recreate open-webui
```

## 5. 数据管理

数据存于命名卷：`openwebui-data`、`postgres-data`、`redis-data`。

```powershell
# ⚠️ 危险操作：清空全部数据（开发期重置用，执行前必须确认）
docker compose -f $cc down -v

# 只停容器保留数据
docker compose -f $cc down
```

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| `failed to connect to the docker API` | Docker Desktop 未启动，见第 2 节第 0 步 |
| 端口被占用 | `netstat -ano | findstr <port>` 找 PID → `taskkill //f //pid <PID>` → 重启 |
| 镜像拉取慢/失败 | 重试；或在 Docker Desktop → Settings → Docker Engine 配置镜像加速后 `docker compose pull` |
| Open WebUI 首次启动慢 | 首次需初始化内置数据库，等 `/health` 返回 200（通常 < 60s） |
| 忘记 PostgreSQL 密码 | 查看 `deploy\.env`（该文件不入库，仅本地存在） |

## 8. 安全提醒

- `deploy\.env` 含数据库密码，已被 `.gitignore` 排除，**严禁提交**
- 提交前自查：`git status` 中不得出现 `.env`
- 本环境仅监听本机端口，勿将 3000 端口直接暴露公网
