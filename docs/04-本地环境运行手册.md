## 2. 首次启动

```powershell
# 0. 前置：启动 Docker Desktop 并等待就绪
Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"

# 1. 检查端口占用（规范要求，启动前必做）
netstat -ano | findstr ":3000 :5432 :6379 :7997"   # 无输出 = 空闲

# 2. 生成 .env（模板在 deploy\.env.example，密码用随机强密码）
#    PowerShell 生成 32 位十六进制密码：
-join ((1..32) | ForEach-Object { '{0:x}' -f (Get-Random -Max 16) })

# 3. 启动
docker compose -f "D:\ai_play\ai_long_project\deploy\docker-compose.yml" up -d

# 4. 验证
docker compose -f "D:\ai_play\ai_long_project\deploy\docker-compose.yml" ps
Invoke-WebRequest -Uri "http://localhost:3000/health" -UseBasicParsing   # Open WebUI，期望 200
Invoke-WebRequest -Uri "http://localhost:8100/healthz" -UseBasicParsing  # memory-service 存活
Invoke-WebRequest -Uri "http://localhost:8100/readyz" -UseBasicParsing   # 就绪（PG+Redis 连通）
```

### 2.4 Embedding 配置（M-04 记忆抽取/检索）

记忆向量由本地 **infinity** 容器承载 `BAAI/bge-m3`（1024 维，OpenAI 兼容
`/embeddings`），模型从宿主机目录只读挂载，**无需下载、不出网**：

```ini
# deploy\.env 默认值即可工作；仅当模型目录不同才需要改
EMBEDDING_MODELS_DIR=D:\ai_models\modelscope_cache\models
EMBEDDING_PORT=7997
# 以下两项为容器网络内部地址，一般不改
# EMBEDDING_BASE_URL=http://embedding:7997
# 模型名是 infinity 注册名（repo id）而非挂载路径：路径式名会被 400 拒绝
# EMBEDDING_MODEL=BAAI/bge-m3
```

验证（期望返回 `dim=1024 model=BAAI/bge-m3`）：

```powershell
$body = '{"model": "BAAI/bge-m3", "input": ["你好"]}'
(Invoke-RestMethod -Uri http://localhost:7997/embeddings -Method Post `
  -ContentType "application/json" -Body $body).data[0].embedding.Count
```

行为说明：embedding 服务不可用时 memory-service **自动降级**（记忆仅走 key
判重入库、检索返回空），不影响对话主链路，故不设硬健康检查依赖。
抽取模型可用便宜小模型：`EXTRACTOR_MODEL=qwen-turbo`（留空复用 LLM_MODEL）。

### 2.5 上下文预算与 preview（M-05 Context Builder）

上下文组装的 token 预算由 `config\budgets\*.yaml` 驱动（YAML 写**占比**，分母 =
`MEMORY_SERVICE_CONTEXT_WINDOW_TOKENS − reserve_output`，调整窗口无需改 YAML）：

| 文件 | 用途 |
|---|---|
| `default.yaml` | 默认：working 30% / rag 25% / semantic 15% / episodic 10% / tool 10% / 偏好 5% |
| `memory_first.yaml` | A/B 备选：记忆区块（semantic 等）加大、rag 压缩 |
| `knowledge_first.yaml` | A/B 备选：rag 加大、记忆区块压缩 |

部署要点（compose 已配置，默认无需改动）：

```ini
# deploy\.env 可选项（默认值即可工作）
# CONFIG_DIR=../config                        # 只读挂载到容器 /app/config
# MEMORY_SERVICE_CONTEXT_BUDGET_PROFILE=default  # 换 profile 走这里
```

- 容器内目录解析：`MEMORY_SERVICE_BUDGET_CONFIG_DIR=/app/config/budgets`（compose 注入）；本地开发/pytest 自动探测仓库根 `config\budgets`
- 找不到配置 **fail fast**（`BudgetConfigError`，preview 返回 500），绝不静默兜底
- YAML 变更需重启 memory-service 生效（进程内 lru_cache）

**preview 调试端点**（M-05 起可用，返回装配明细）：

```powershell
# 登录取 token 后（同 §9.1 Pipe 账号或任意注册用户）
$body = [System.Text.Encoding]::UTF8.GetBytes('{"workspace_id":"<ws-id>","session_id":"<sid>","query":"用户的城市偏好是什么？"}')
(Invoke-RestMethod -Uri http://localhost:8100/api/context/preview -Method Post `
  -Headers @{Authorization="Bearer <token>"} `
  -ContentType "application/json; charset=utf-8" -Body $body) | ConvertTo-Json -Depth 6
```

响应含 `profile` / `window_tokens` / `available_tokens` / `total_tokens` /
`sections[]`（各区块 budget/included/dropped/tokens）与最终 `messages[]`——
演示"记忆如何被注入"与排查预算分配的主要工具。跨 workspace 返回 403。

### 2.6 记忆管理与用量统计（M-11）

记忆面板后端端点（均需 Bearer token + `workspace_id` 参数；跨 workspace 403 防枚举）：

| 端点 | 说明 |
|---|---|
| `GET /api/memories?workspace_id=<ws>` | 列表：`memory_type` / `status` / `q`（key/content 关键词）过滤 + `limit/offset` 分页；conflicted 置顶，软删除恒排除 |
| `GET /api/memories/{id}?workspace_id=<ws>` | 详情：`version_chain[]`（被替代历史，沿 supersedes 上溯）+ `events[]`（事件流水） |
| `PATCH /api/memories/{id}?workspace_id=<ws>` | 用户编辑：`content` / `confidence` / `importance` / `expires_at`（提交 null 清除 TTL）；version+1，落 `edit_by_user/user` 审计 |
| `DELETE /api/memories/{id}?workspace_id=<ws>` | 软删除（204，幂等）；列表与检索不再可见 |
| `POST /api/memories/{id}/resolve?workspace_id=<ws>` | 冲突裁决：body `{"keep":"this"|"other"}`；保留者回 active 并挂版本链，另一条 superseded |
| `POST /api/memories/search?workspace_id=<ws>` | 检索测试：body `{"query":"…","top_k":10}`，与对话链路同一检索器；embedding 未配置返回空列表 |
| `GET /api/usage/summary?workspace_id=<ws>&days=7` | 用量聚合：totals（含 memory/rag/tool 区块拆分）+ sessions/turns/by_day（UTC 日界，days 1-90） |

用法示例（PowerShell，中文 body 必须 UTF8 字节，见 §9.1 取 token）：

```powershell
# 列表（conflicted 优先展示，供裁决入口）
Invoke-RestMethod -Uri "http://localhost:8100/api/memories?workspace_id=<ws>&status=conflicted" `
  -Headers @{Authorization="Bearer <token>"}

# 编辑（expires_at 提交 null 表示清除 TTL）
$body = [System.Text.Encoding]::UTF8.GetBytes('{"content":"新内容","confidence":0.9}')
Invoke-RestMethod -Uri "http://localhost:8100/api/memories/<id>?workspace_id=<ws>" `
  -Method Patch -Headers @{Authorization="Bearer <token>"} `
  -ContentType "application/json; charset=utf-8" -Body $body
```

用量口径：chat 每轮自动落 `token_usages`（prompt/completion 优先上游 usage，
流式缺失时本地估算）；`by_day` 为 UTC 日界，本地化展示由前端换算。

### 2.7 知识库与混合检索（M-07）

RAG 知识库端点（均需 Bearer token + `workspace_id` 参数）：

| 端点 | 说明 |
|---|---|
| `POST /api/knowledge/files?workspace_id=<ws>` | 上传（multipart `file` 字段；支持 pdf/docx/md/txt，默认上限 20MB）；同步解析+切片+分词入库后返回 201（状态 `parsing`），embedding 后台补齐至 `embedded`（失败 `failed`，重传同文件即重试） |
| `GET /api/knowledge/files?workspace_id=<ws>` | 文件列表（created_at 倒序，含 status/version/chunk_count） |
| `DELETE /api/knowledge/files/{id}?workspace_id=<ws>` | 硬删（204，级联删 chunk；再删 404） |
| `POST /api/knowledge/search?workspace_id=<ws>` | 检索调试：body `{"query":"…","top_k":6}`，与 chat 链路同一混合检索器（向量+BM25→RRF→rerank） |

行为要点：

- **同名重传**自动 version+1，旧版置 `superseded`（向量与分词双路下线，文本保留可追溯）；**同内容重传**幂等返回已有文件
- chat 对话自动检索知识库（RAG 区块注入），回答的 `metadata.citations`（非流式）与流式 finish 分片均携带 `{filename, chunk_index, chunk_id, …}` 引用定位
- rerank/embedding 任一服务不可用时自动降级（BM25 直排 / 跳过该路），不阻断对话

冒烟评测（真实链路 Recall@K，服务已启动时）：

```powershell
cd services\memory-service
& .\.venv\Scripts\python.exe evals\rag_recall.py            # 默认 top_k=5
# 期望：Recall@5 = 10/10（M-07 实测 100%、MRR=1.000）
```

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| `failed to connect to the docker API` | Docker Desktop 未启动，见第 2 节第 0 步 |
| 端口被占用 | `netstat -ano | findstr <port>` 找 PID → `taskkill //f //pid <PID>` → 重启 |
| 镜像拉取慢/失败 | 重试；或在 Docker Desktop → Settings → Docker Engine 配置镜像加速后 `docker compose pull` |
| Open WebUI 首次启动慢 | 首次需初始化内置数据库，等 `/health` 返回 200（通常 < 60s） |
| 忘记 PostgreSQL 密码 | 查看 `deploy\.env`（该文件不入库，仅本地存在） |

## 9. Open WebUI 对接 memory-service（EchoDesk Memory Pipe，M-08）

Open WebUI 通过 **Pipe 管道函数** 与 memory-service 对话（不能走 Settings→Connections 直连：
直连不会携带 EchoDesk 必需的 `metadata.workspace_id`）。Pipe 代码在
`deploy\pipes\echodesk_memory.py`（入库版本管理）。

### 9.1 前置：Pipe 服务账号

Pipe 用专用服务账号 `openwebui_pipe` 访问 memory-service（已注册，密码记录在
`deploy\.env` 的 `ECHODESK_PIPE_PASSWORD`）。M1 阶段所有 Open WebUI 用户共用该账号的
个人 workspace；按用户映射 EchoDesk 账户属于后续集成工作。

### 9.2 安装步骤（浏览器操作，管理员账号）

1. 打开 `http://localhost:3000` → 右上角头像 → **管理员面板**
2. **函数（Functions）** → `+` 新建函数 → 标题填 `EchoDesk Memory`
3. 把 `deploy\pipes\echodesk_memory.py` 的**全部内容**粘贴进代码编辑区 → 保存
4. 回到函数列表 → 打开该函数的**阀门（Valves）** → 填写
   `ECHODESK_PASSWORD`（即 `deploy\.env` 里的 `ECHODESK_PIPE_PASSWORD` 值）→ 保存
5. 确认函数已启用 → 新建对话 → 模型选择器中出现 **EchoDesk Memory** → 对话即走 memory-service

### 9.3 验证要点

- 对话有流式回答（经通义千问）
- 追问上一轮说过的信息（如"我最喜欢的颜色"），模型能答对 → Working Memory 多轮生效
- 对话标题自动生成（Open WebUI 任务调用走 `/v1/tasks/completions` 无状态端点，不污染会话）
- `GET http://localhost:8100/api/sessions?workspace_id=<ws>`（openwebui_pipe 登录态）
  能看到 Open WebUI 对话产生的会话与消息
- 排障：`docker logs workbench-openwebui 2>&1 | findstr echodesk-pipe` 查看 Pipe 观测日志

### 9.4 已知限制（M1 直通）

- chat_id → session_id 映射存 Pipe 进程内存：Open WebUI 重启后，旧对话再发消息会开新会话
- Open WebUI 页面内删除对话不会同步删除 EchoDesk 会话（可在 EchoDesk 侧管理）
