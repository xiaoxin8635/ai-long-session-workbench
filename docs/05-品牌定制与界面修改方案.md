## 1. 品牌定义

| 项 | 值 |
|---|---|
| 品牌名 | **EchoDesk** |
| 中文副标题 | AI 长会话知识工作台 |
| Slogan | "Your AI remembers." / 它记得你说过的每一句 |
| 品牌隐喻 | Echo（回声）= AI 对用户历史记忆的回响；Desk（工作台）= 求职/学习的生产力场景 |

## 2. License 合规分析（必读）

Open WebUI 采用自定义 **Open WebUI License**（非 MIT）。与品牌定制直接相关的是**第 4 条**：

> 原文要点：除非满足以下任一条件，否则严格禁止更改、移除、遮挡或替换任何 "Open WebUI" 品牌（名称、logo 及一切视觉/文本/符号标识）：
> (i) 滚动 30 天内终端用户 ≤ **50 人**的部署；
> (ii) 获得版权方书面许可；
> (iii) 持有企业授权。

### 本项目的合规结论

| 判断 | 说明 |
|---|---|
| ✅ 可自由改名换肤 | 本项目为个人项目，实际用户 = 本人（远低于 50 人），适用例外条款 (i)，**合法允许**将名称/logo/品牌替换为 EchoDesk |
| ⚠️ 超过 50 人即失效 | 若未来公开服务超过 50 用户，需恢复 Open WebUI 品牌或获取授权——在 `docs/06` 公共约定中留检查项 |
| ✅ 版权与许可文件必须保留 | 源码分发（含公开仓库）须保留 LICENSE 与版权声明（第 1、2 条） |
| ✅ 不得以 Open WebUI 名义推广 | 衍生品推广只能用 EchoDesk 名义（第 3 条） |

### 我们的执行口径（诚实叙事优先）

- README 首屏保留 **"Built on Open WebUI"** 署名 + 上游链接 + 模块来源表（非 license 强制，但面试叙事最佳实践）
- 仓库内涉及 Open WebUI 衍生代码处保留其版权头与 LICENSE 文件
- 界面内（如"关于"页）保留一行 "Powered by Open WebUI"（可选但推荐）

## 3. 定制分层策略

品牌定制按"改动成本从低到高"分三层，**各里程碑按需启用**：

| 层 | 改动内容 | 是否需 fork 源码 | 启用时机 |
|---|---|---|---|
| Layer 1 | 站名、favicon、logo 资产、主题色 | ❌ 官方镜像 + 环境变量/挂载即可 | M1 立即 |
| Layer 2 | 登录页文案、界面语言细节、PWA 信息 | ✅ 轻量（fork 后只改 i18n/静态文件） | M2 末期 |
| Layer 3 | 新增页面：记忆面板、用量看板、冲突裁决 | ✅ SvelteKit 路由级开发 | M3（Day 9 起） |

> 策略含义：M1/M2 阶段继续使用官方镜像 + Pipe 对接，不被前端工程阻塞后端主线；M3 阶段一次性 fork 构建 EchoDesk 专属镜像。Layer 3 页面在 fork 前可先用独立轻量页（React/Streamlit 挂到 8100 端点）过渡，API 契约不变。

## 4. Layer 1：官方支持的环境变量定制（零代码）

修改 `deploy/docker-compose.yml` 的 `open-webui` 服务：

```yaml
    environment:
      # ---- EchoDesk 品牌（Layer 1）----
      WEBUI_NAME: "EchoDesk"                       # 站名：浏览器标题 / PWA 名称 / 侧边栏
      WEBUI_FAVICON_URL: "/static/favicon.png"     # favicon（配合下方资产挂载）
      WEBUI_AUTH: "True"
      TZ: Asia/Shanghai
    volumes:
      - openwebui-data:/app/backend/data
      # ---- 品牌资产挂载（Layer 1）----
      - ../brand/static:/app/build/static:ro       # 本地 brand/ 目录覆盖静态资产（logo 等）
```

主题与品牌色（**不改代码，管理面板操作**）：

1. 以管理员登录 → Admin Panel → Settings → **Interface**
2. 设置 Theme：Light / Dark（用户侧个人可切换，满足"双主题"）
3. 设置主题色为 `#4F46E5`（或用户在浅/深两套主题分别设置主色）
4. 其余（背景、字体、圆角）保持默认，保证升级兼容

> ⚠️ 落地核对项：`/app/build/static` 内 logo/favicon 的准确文件名随版本可能变化。实施时执行：
> `docker exec workbench-openwebui find /app/build/static -maxdepth 1 -name "*.png" -o -name "*.svg" -o -name "*.ico"`
> 将 `brand/static/` 内文件按同名对应放置。此核对步骤已列入 Day 2 清单。

## 5. Layer 2：轻量二开（文案与资产）

fork 上游仓库后仅做小范围修改（保持与上游的可同步性）：

| 改动点 | 位置（以实际版本核对） | 内容 |
|---|---|---|
| 登录页欢迎文案 | `src/lib/i18n/locales/*/translation.json` 中相关 key | "Sign in to EchoDesk — Your AI remembers." |
| 默认描述文案 | i18n 同上 | 品牌一句话介绍 |
| PWA manifest | `static/manifest.json`（构建配置） | name/short_name → EchoDesk；图标换品牌资产 |
| 关于页署名 | about 相关组件 | 增加 "Powered by Open WebUI"（合规口径） |
| 仓库级版权 | 不改动 | 上游 LICENSE、版权头原样保留 |

**fork 同步纪律**：所有 Layer 2/3 改动集中放 `echodesk/` 前缀目录或独立分支 `echodesk/branding`，方便对照上游更新（记录上游 base 版本 tag）。

## 6. Layer 3：功能二开（新增界面）

在 fork 的 SvelteKit 前端中新增三个页面（数据全部来自 memory-service REST API，见 `docs/06` M-11/M-12 规格）：

| 页面 | 路由（建议） | 侧边栏入口 | 功能 |
|---|---|---|---|
| 记忆面板 | `/(app)/memory` | 🧠 记忆 | 四层记忆列表/筛选/详情/编辑/删除/冲突裁决 |
| 用量看板 | `/(app)/usage` | 📊 用量 | token 成本按区块/会话/日期统计图表 |
| 知识库增强 | `/(app)/knowledge`（上游已有页增强） | 📚 知识 | 上传进度、切片预览、检索调试 |

> 上游已有的会话/知识库页面优先复用增强，不重复造页面。新增页面统一走 `src/lib/apis/` 下新建的 `memory.ts` 客户端模块调用 memory-service。

## 7. 新增界面设计（低保真）

### 7.1 记忆面板（核心新界面）

```text
┌─────────────────────────────────────────────────────────────┐
│ 记忆管理                                       [+ 手动添加]  │
├─────────────────────────────────────────────────────────────┤
│ 筛选: [全部▾] [类型: 事实/偏好/事件▾] [状态: 正常/冲突/过期▾] │
│       [搜索关键词________]                    共 128 条记忆  │
├─────────────────────────────────────────────────────────────┤
│ ⚠ 冲突  skill.frontend        用户不熟悉前端 (v2, 置信0.9)   │
│         └ 旧: 用户熟悉前端 (v1) [保留新版] [保留旧版] [查看来源]│
├─────────────────────────────────────────────────────────────┤
│ 📌 偏好  reply.style          先给结论再给细节                 │
│         置信 0.95 · 来源: 3天前会话"面试准备" · 命中 12 次     │
│         [编辑] [删除] [溯源→]                                 │
├─────────────────────────────────────────────────────────────┤
│ 🧠 事实  job.字节.进度        三面通过，等 HR 面 (2026-09-15)  │
│         置信 0.88 · TTL 30天(剩12天) · [编辑] [删除] [溯源→]  │
└─────────────────────────────────────────────────────────────┘
```

交互要点：
- 冲突记忆置顶 + 高亮，裁决操作调用 `POST /api/memories/{id}/resolve`
- "溯源"跳转到来源会话的对应消息（`source_session_id` + `source_message_ids`）
- 编辑走 `PATCH /api/memories/{id}`，全部操作落 `memory_events` 审计

### 7.2 用量看板

```text
┌────────────────────────────────────────────┐
│ 本周 token 成本        区块占比(最近7天)     │
│  ████ 总计 1.2M        ▓偏好  6%            │
│  较上周 ↓ 31%          ▓事实  14%           │
│                        ▓摘要  11%           │
│  会话数 23   轮次 410   ▓近期消息 29%        │

│                        ▓工具  9%  ▓其他 5%  │
└────────────────────────────────────────────┘
```

数据源：`GET /api/usage/summary`（聚合 `token_usages` 表）。

## 9. 实施顺序与验收

| 阶段 | 任务 | 验收标准 |
|---|---|---|
| M1（立即） | Layer 1：`WEBUI_NAME=EchoDesk` + favicon/logo 挂载 + 管理面板主题色 | 浏览器标题显示 EchoDesk；双主题切换正常；主色为靛蓝 |
| M2 末期 | Layer 2：fork 仓库、i18n 文案、PWA、登录页 | 登录页显示品牌文案；PWA 安装名为 EchoDesk |
| M3 Day 9+ | Layer 3：记忆面板 → 用量看板 → 冲突裁决交互 | 三页面对接 memory-service API 全部可用 |
| 持续 | 合规检查：README 署名、LICENSE 保留、50 人阈值监控 | 每次发版前过一遍合规清单 |

> ⚠️ 风险提示：Layer 1 的静态资产路径需按实际镜像版本核对（见第 4 节核对命令）；Layer 2/3 fork 后需记录上游 base tag，升级上游时逐项 rebase 品牌补丁。
